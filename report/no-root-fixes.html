FIX-01NF-02：安装脚本停止 agent 时不再误杀同机其它 agentdeploy/install-agent.sh

结论：nohup 回退分支不再按名字整机匹配；只停「自己上一次起的那个进程」，并且停之前用 /proc/<pid>/cmdline 核对 PID 没被复用。

为什么这算「无 root 缺陷」：这台机器上用户自己的 systemctl --user agent（PID 266643）与脚本启的 agent 同名同用户。旧的 pkill -f clusterscope-agent 会把别人的、以及生产实例一起杀掉——一次安装事故，且在被杀方看来毫无线索。

修复前（7ca587a）
-    pkill -f clusterscope-agent 2>/dev/null || true
-    nohup "$HOME/.local/bin/clusterscope-agent" -c "$HOME/.config/clusterscope/agent.yaml" \
-        >> "$HOME/.config/clusterscope/logs/agent.log" 2>&1 &
修复后（1279b48）
+    stop_previous_agent            # 读自己的 pidfile；cmdline 不匹配就 "leaving it alone"
+    nohup "$BIN" -c "$CONF" >> "$HOME/.config/clusterscope/logs/agent.log" 2>&1 &
+    echo "$!" > "$PIDFILE"         # ~/.config/clusterscope/agent.pid

结论：显式给了 -c/--config 而文件不存在时，agent 立即以非 0 退出，错误里逐字点名那个路径并给出用户级位置；不再回退到内置默认值（即不再出现 http://localhost:50051）。不带 -c 且默认 /etc/clusterscope/agent.yaml 缺失时，仍然「告警 + 继续跑」（守住 NR-06：不崩）。

为什么算「无 root 缺陷」：照抄系统级 unit（ExecStart=… --config /etc/clusterscope/agent.yaml）的人，在用户级安装下必然没有 /etc/… 这个文件。旧行为是静默用默认值继续跑，节点连到 localhost:50051，表现为「agent 起来了但永远不上线」，报错完全指不到配置文件。

修复前（7ca587a）
-    // Try to load from file

-    // 输出里没有提到 config_path 的任何一行
修复后（1279b48）
+    Some(path) => required_config_file(path),          // 缺失即 bail!
+    None if default_path.exists() => read_config_file(default_path),
+    None => { warn!("{default_config_missing_message}"); Ok(AgentConfig::default()) }
